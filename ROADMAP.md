## Public Incubation and Awesome Submission

The public GitHub repository starts the incubation clock. Before proposing the list to the canonical Awesome index:

- [ ] create the public repository with default branch `main`;
- [ ] add the GitHub topics `awesome`, `awesome-list`, `intent-engineering`, `ai-agents`, and `spec-driven-development`;
- [ ] publish the `v0.2.0` seed release;
- [ ] have the maintainer manually review, rewrite where necessary, and take responsibility for every catalog entry;
- [ ] keep the public list active for at least 30 days;
- [ ] run the manual `Awesome lint` workflow and resolve every reported issue;
- [ ] verify that included projects remain maintained, documented, and available;
- [ ] review four open pull requests in the canonical Awesome repository before submitting its required pull request;
- [ ] document the four reviews and submit only after the list reflects substantive human curation.

The manual lint workflow is intentionally not attached to every pull request during the first 30 days because `awesome-lint` includes a repository-age rule.

Target conditions:

- taxonomy validated against at least 30 substantive resources;
- multiple maintainers review inclusion decisions;
- every active project verified within 90 days;
